# Agent Note: 小说插图来源、图文缓存与阅读位置迁移

Status: implemented

## Problem

用户提供的《让你氪金修仙，没让你包养女剑仙》（别名《氪金仙尊：首充6元即赠绝色剑仙》，书 ID `7442050065109109822`）第 1 章包含 3 张插图，客户端只显示图注。问题同时存在于正文来源和显示链路：FM full 正文已经没有图片，旧规范化函数会剔除图片，磁盘缓存和分页只认识文字。直接切换接口或重新下载旧缓存都无法独立解决。

## Decision

[ApiClient.chapterContent](../../../../lib/services/api_client.dart) 优先调用 `/api/v1/chapters/{id}/novel`。对应的 `/internal/endpoints/base.go` 使用已有 `support_image=1` 上游参数，并把响应头 `c=1` 视为加密标志，从 JSON `data.content` 取密文；旧版把密文放在 `c` 头中的协议仍兼容。解密必须成功且产生非空 UTF-8，随后增加 `data.content_decrypted=true`。客户端只接受这个成功标记，防止旧后端返回 `code=0` 却将密文显示为正文。

图文接口失败时保留原 `contentText` 作为文字回退，并标记尚未完成插图检查。原纯文字接口与 TXT 导出保持原协议。完整支持要求从配套 `` 源码重建 JNI 后端；仅更新 Flutter 不足以取回插图。[CI 工作流](../../../../.github/workflows/android-apk.yml) 固定 `` 提交 `b2379115307295651e2e7b09c7ea74e438aa4b46` 并原样构建，完整 Go 测试通过后才编译 JNI，构建报告记录该提交。解密契约测试与剧集标题索引修复曾以 [App 后端补丁](../../../../patches//README.md) 的形式随 App 保存，现已并入 `` 历史（分支 `fqapp-android`）并退休，退休前后的文件逐字节一致。

[ChapterContent](../../../../lib/services/chapter_text_formatter.dart) 在隔离线程中解析上游 HTML，顺序保存段落与插图，识别 `img-width/img-height`、常见尺寸和懒加载字段，只允许 HTTP(S) 图片地址。HTML 实体仅解析一次，绝对签名 URL 不重新编码。重复图片和纯图片章节是有效内容。缓存使用显式版本前缀和 JSON，保留块、旧规范化文字及检查状态；无前缀的缓存按纯文字读取，不再次解释书中提到的字面标签。

[阅读布局](../../../../lib/widgets/reader/reader_chapter_layout.dart) 以尺寸比例预留插图高度，最大不超过一页，未知尺寸默认使用 3:4 占位。图片加载后不重新测量正文。[ReaderIllustration](../../../../lib/widgets/reader/reader_illustration.dart) 用 contain 保持比例，失败时提供单图重试，点击进入可双指缩放的全屏页。分页与滚动共用图文块；图片在分页时不可拆分。空标题在两种模式下都不增加段距。

位置格式扩展为 v2：文字按 UTF-16 计数，每个图片块占一个 U+FFFC 字符，块间换行，连续图片可独立定位。v1 文字偏移通过保留的旧规范化正文映射，包含段内插图拆分段落的情况。字体、横竖屏和阅读方式改变时仍保留同一锚点，沿用 [分页决定](../feature/2026-09-10-reader-pagination.md)。

[ReaderPage](../../../../lib/pages/reader_page.dart) 先显示旧缓存，再去重请求补图。已保存的插图不会被临时文字回退覆盖；图片 URL 的 `x-expires` 即将过期时，打开章节或恢复前台会刷新。补图早于初次布局时保留原历史及从末页进入的意图；晚于切章时只更新对应缓存，只有当前章节 ID 匹配才更新页面，离开后再次返回同章也可接收在途结果。退出后返回的网络结果不写回已清理缓存，磁盘写入失败不阻止已获取图文显示。

[批量缓存面板](../../../../lib/widgets/chapter_cache_sheet.dart) 和阅读器通过 `ChapterContent.preferCompleteCache` 保留已有可读图文，只有完成插图检查的新内容可替换它。批量请求结束后重新读取缓存，避免基于请求前的旧快照覆盖同时完成的更新；没有旧缓存时仍保存文字回退，并提示“插图未更新”，不宣称完整缓存成功。

图文可用后，面板通过 `onContentAvailable` 同步阅读器内存并递增对应章节的缓存版本，然后立即进入既有的串行磁盘写入队列。内容相同的缓存命中不递增版本，避免批量回退保留旧图时取消正在进行的有效签名刷新。提前发布版本可阻止旧预取在新写入之后排队；写入失败时已下载的图文仍可在当前阅读器使用。旧磁盘读取或网络结果返回时核对版本，失效结果改用最新缓存。内存最多保留五章，批量下载不淘汰当前章。网络 loader 不修改永久“已请求”集合；单次加载结果携带是否刚从网络获取，避免紧接文字回退重复请求，同时允许后续进入旧缓存时重新补图。取消或关闭面板后的网络结果不会发布缓存或压制阅读器补图。

## Alternatives considered

- 从 FM full/mget 解密原文保留 HTML：能复用原有批量加载和缓存，改动较小；实测 full 正文的图片容器已经为空，添加 `support_image=1` 也只有图注，因此无法恢复本书插图。
- 直接在 WebView 或通用 HTML 组件中显示正文：能快速覆盖更多标签，但已有完整行分页、精确滚动范围和跨字体位置恢复需要共用 Flutter 测量，另建页面布局会使这些行为分叉。当前保留需要的段落与图片模型。
- 图片加载后按真实尺寸重新分页：对缺少尺寸的上游更精确，但会改变总页数和正在阅读的位置。使用有限的固定槽位并提供原比例全屏查看，代价是未知尺寸可能出现留白。
- 缓存章节时预下载全部插图：能首次离线显示所有图，但会引入额外下载容量、取消和淘汰管理。本次存储图文元数据，图片显示时交由现有图片缓存下载；缓存面板明确说明首次查看插图需要联网。
- 批量缓存后清空全部阅读器内存：实现简单，但下一章仍可能接收正在进行的旧预取，而且当前阅读布局无法及时更新。采用按章节发布内容与版本校验，保留既有阅读锚点。
- 只等待后端仓库发布新提交再调整 CI：可以不维护补丁，但当前后端修复尚未发布，云端会继续构建不满足客户端解密契约的源码。固定已存在的基础提交并随 App 保存可校验补丁，能够在发布后端之前复现构建；代价是上游合入后必须成对删除补丁并更新固定版本。

## Verification

[正文测试](../../../../test/chapter_content_test.dart) 覆盖真实标签、尺寸、图文顺序、签名 URL、缓存往返、字面实体、损坏结构、过期判断，以及解密标记与纯文字回退。`/internal/endpoints/content_decryption_test.go` 使用合成 DH/AES-CBC 样本验证新旧头格式、图片元数据、错误密文和非法 UTF-8。

[布局测试](../../../../test/reader_chapter_layout_test.dart) 检查不同窗口下整图分页、纯图无标题、图片偏移、v1 段内图片迁移和 v2 跨模式定位。[插图交互测试](../../../../test/reader_illustrations_test.dart) 覆盖晚加载、点击与缩放、失败重试、两种模式离线缓存、补图前后锚点、首次布局竞争、过期回退与恢复、切章返回、退出后清缓存和损坏缓存恢复。批量缓存回归另覆盖下一章预取已完成、旧磁盘读取迟到、旧网络回退迟到、新内容正在写盘、取消后继续阅读；[面板测试](../../../../test/chapter_cache_sheet_test.dart) 区分保留旧插图与首次文字回退的提示。后端契约测试在未修复基础提交上失败，应用配套补丁后 Go 全量测试通过。真实图文接口、原图下载与原交付记录见 [插图验证记录](../../../../docs/reader-illustrations-validation-20260910.md)，本轮缓存、分页及 CI 验证见 [审查修复记录](../../../../docs/review-fixes-validation-20260910.md)。

## Consequences

本书第 1 章的 3 张插图可按原顺序阅读和放大，旧文字缓存不需要手动删除，已经阅读的文字位置可迁移到图文布局。代价是新正文来源和缓存版本需要共同维护，首次打开旧缓存额外请求一次正文，图文来源失败时新章节只能暂时显示文字。

图片文件由现有图片缓存按需存储，并不计入章节缓存的 80 MB 正文限额；批量缓存章节不承诺未打开的插图首次离线可用。签名刷新依赖上游在线，正文被作者修改后的语义位置也无法仅靠字符偏移保证。如果上游开始持续缺少尺寸或出现更复杂图文布局，应重新评估固定占位和结构化块模型。
