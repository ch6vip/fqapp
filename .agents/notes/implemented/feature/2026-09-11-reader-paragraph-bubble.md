# Agent Note: 阅读器正文内联段评气泡

Status: implemented

## Problem

段评此前只在阅读器菜单里有一个「段评 · N」入口，点开是**按段落分组的底部面板**。正文本身没有任何标记：读者读到一段有话想说的地方，看不出这段有没有人评过，必须先收菜单、找入口、再在面板里翻到那一段。

官方客户端是在正文里直接画气泡的，这也是用户这次要的效果。

需要先说明的是：本文推翻了自己上一篇结论。[章评／段评端点](2026-09-10-chapter-ideas-endpoint.md) 当时把内联角标列为**否掉**的方案，理由是「需要改动分页布局逐行的命中测试，风险高于收益」。这次做了，做法与当时的顾虑不同——见下。

本文随后又推翻了自己的**第一版实现**（门槛与气泡外观都错了），那部分作为「踩过的坑」保留在下面，因为它正是真机反馈暴露出来的。

## Decision

在段落**末行末尾**内联一个**空心圆圈**气泡，圈内是段评数，点它直接打开该段的段评。

### 哪些段落有气泡：只要 `count > 0`

**第一版做错了。** 我读到官方 `CSSParagraphCommentReaderService` 里有：

```java
if (com.dragon.community.impl.d.a.a().a().b() && readerSwitchService().o(...)) {
    paraBubble = (ParaBubble) CollectionKt.getOrNull(paraIdeaData.bubbleData, 3);
    if (paraBubble == null || paraBubble.count <= 0) return;   // 不画
}
int i2 = paraIdeaData.count;                                    // 画的是这个
```

就把 `bubble_data["3"].count > 0` 当成了**无条件门槛**。它在一本测试书上恰好放行 21/48 段，看起来"很合理"，于是没再怀疑。

真机反馈是「怎么只有第一个段落有段评」。回来查那本真机上的书（`茅山鬼术，只杀不度` 第 1 章，36 段）：

| 判据 | 通过段数 |
|---|---|
| `count > 0` | **36 / 36** |
| `bubble_data["1"].count > 0` | 36 / 36 |
| `bubble_data["3"].count > 0` | **1 / 36** |

同一判据在两本书上是 21/48 与 1/36 —— 这种不稳定本身就说明判据错了。回头补看**外层条件**才发现它是 AB 开关：

- `d.a.a().a()` = `lr1.s`，`bp4.a.b()` 的实现是 `ParaCommentFeatured.a.a().enableParaFeatured`；
- 该开关读远程配置 **`para_comment_featured_v697`，默认 `false`**（`mr1.e.b()` 也直接返回 `false`）。

也就是说：**官方默认根本不施加这道门槛**，`count > 0` 就画。门槛只在 AB 打开时才生效，而它比看上去严得多（段落可以在别的通道有段评而 `bubble_data[3]` 为 0）。

现在的实现：`showsBubble => hasIdeas`。`bubbleGateChannel` 常量保留，用于在代码里记录这段通道语义与决策出处。

### 气泡长什么样：空心圈，不是实心圆

**第一版也做错了。** 我按"番茄红/暖纸"自己设计了一个**半透明实心灰圆**。用户的第二问是「段评气泡为什么不用番茄小说的」。

于是把官方素材挖出来。皮肤接口 `l94.e` 的默认实现 `m94.d` 把每个方法映射到具体资源 id，逐层解析 `public.xml` 后拿到真实图片：

| 分支 | SMALL | NORMAL | LARGE |
|---|---|---|---|
| `Type.d()` | `drawable/cnq` | `drawable/cnr` | `drawable/dbe` |
| `Type.a()` | `drawable/cne` | `drawable/cnf` | — |
| 其他 | `drawable/cni` | `drawable/cnj` | `drawable/cnk` |

把这些 webp 解码后逐像素分析，三点结论：

1. **它们是纯黑 + alpha 的蒙版，不含颜色** —— 颜色由 `p.o(drawable, color)` 用主题文字色着色（暗色模式下再按 0.6/0.7 调透明度）。所以气泡颜色**应当跟随阅读主题**，不能写死。
2. **是空心圈，不是实心圆**：`cnq` 78×72px 里只有 887/5616 ≈ 15.8% 的像素不透明，横切中心行得到 `4px 描边 → 64px 透明 → 4px 描边`。实心圆该有 ~78%。外层直径 24dp、描边 4px@3x ≈ **1.33dp**。
3. **尺寸分档**（`n02/e.java`）：外径 24 / 26 / 30dp，文字 8 / 9 / 10sp，与正文字号 ≤19 / ≤29 / >29 对应；**间距 8dp**（`ParaBubbleInlineConfig.margin` 的默认值，我第一版用了 6dp）。

`setShowInImage` 只在段落**含图片**时才走另一条 `GradientDrawable`（填充药丸）路径（`b.w()` 由 `a0.c()` 决定），普通文字段落走的就是上面这套图片圈。

数字文案：`q02.a.c()` 在 `getParaBubbleInlineEnable()` 为 false（默认）时用 **≤99 显示原数，>99 显示 `99+`**；开关打开时才改用量级格式。因此实现采用 `99+` 截断。

### 实现方式：气泡进入文本流，不是叠加层

关键决定是**不**把气泡做成覆盖在正文上的独立定位层，而是**排进段落自己的文本流**：把气泡作为 `WidgetSpan` 追加在段落 `TextSpan` 的末尾，并用 `TextPainter.setPlaceholderDimensions` 给它占位。

这样做的好处是命中的是真正的排版结果：

- 气泡天然出现在**末行末尾**，段末放不下时随文本一起换行，不会盖住字；
- 分页测量与绘制用**同一个 span**（`reader_chapter_layout.dart` 里测量用的 `block.span` 就是渲染用的那个），不存在"量出来一个高度、画出来另一个"的偏差；
- 段落内的字一个都没动，气泡纯属追加（有测试断言三段正文仍完整渲染）。

代价与边界：

- 增加了一个 `WidgetSpan`，所以 `\uFFFC` 占位符从 1 个（首行缩进）变成 1~2 个，行内偏移的换算相应调整（`leading` 常量）；
- **"只含气泡的行"不产生切分点**（`cuts` 只在 `starts[i] < text.length` 时新增），因此气泡永远跟着前一行走，不会单独占一页；
- 分页模式下气泡若落在片段被裁切的位置会被 `ClipRect` 裁掉，与正文同一处理，不另做补偿。

### 段评到达要重排版

`_prepareLayout` 原本只在 spec 变化或翻页模式切换时重算布局，而**段评与这两者都无关**。因此加了 `_ideasRevision`：段评变化时 +1，缓存布局记住自己是用哪个 revision 量的，不一致就重算。

这里改动时我自己引入过一个缺陷并被测试当场抓到：重用的判据只看了 spec 与模式，导致段评到达后**直接复用旧布局，气泡永远不出现**（正文正常，只是没气泡——最容易被当成"没数据"的那类静默失败）。修法是把 revision 一并纳入重用条件，同时保住原本"切分页模式不重新测量"的优化。

## Alternatives considered

- **按 `count > 0` 画气泡（现在采用）**：这正是官方默认行为。第一版因为漏看外层 AB 条件而否掉了它，见上文。
- **保留 `bubble_data[3]` 门槛**：第一版的做法。它让气泡只出现在少数段落上，且在两本书上分别放行 21/48 与 1/36 —— 判据本身不稳定，且与官方默认不符。真机反馈「只有第一段有段评」即由此而来。否掉。
- **门槛与显示都用同一个数**：省一层解释，但门槛通道为 0、顶层 `count` 有值的段落大量存在，会与官方数字不符。现在只显示 `count`，问题自然消失。
- **半透明实心圆（第一版外观）**：实现只要一个 `BoxDecoration`，但官方素材实测是**空心圈**，实心圆是另一个控件的样子。用户明确要求番茄样式，否掉。
- **直接引用官方 webp 素材**：最省事也最像，但那是 7.0.9.32 的皮肤资源，把上游位图打包进本项目既有版权问题，也会在换肤后过期。改为按实测的几何（直径、描边、间距）自绘圆圈，并让颜色跟随阅读主题 —— 这正是官方对同一张蒙版所做的（着色而非自带颜色）。
- **写死官方浅色皮肤的灰度**：官方颜色来自 `e.D(themeIndex)`，随皮肤与夜间模式变化；写死会在四种阅读背景之一上不可读。改用阅读主题的 `mutedTextColor`。
- **数字用 `1.2万` 量级格式**：那是官方 `getParaBubbleInlineEnable()` 打开后的分支，默认关闭。默认是 `99+`，因此采用 `99+`。
- **把气泡做成正文之上的 `Stack`/`Positioned` 覆盖层**：不必碰 `reader_chapter_layout.dart`，但需要自己按行高算位置，且测量高度与绘制高度会各算一遍；换行、两端对齐、插图、大字号下都要各自处理。选择排进文本流，让排版器负责定位。
- **给非末行也支持气泡**：官方就是末行，且末行定位不需要额外的行内偏移映射。不做。
- **气泡里显示段评正文摘要**：`infos` 实测恒为空（48 段里 46 段为空数组，另 2 段虽带 id 但 `count=0`），正文要再走一跳 `insert_comment_ids`。官方面板里气泡也只有数字。不做。
- **点击气泡跳转段评列表页**：官方是弹面板；本项目已有 `ReaderIdeasSheet`，复用它成本最低，且不新增导航层级。

## Consequences

- 正文里能直接看到哪些段落有讨论及数量；点气泡**直接打开面板并展开那一段**（`initialParaIndex`，面板会把该段滚入视野），不再需要自己翻找。
- 气泡是**空心圈**，圈内是数字，颜色跟随阅读主题（四种背景与夜间模式都成立），几何按官方规格：外径 24/26/30dp、描边 1.33dp、间距 8dp、文字 8/9/10sp。
- 标签在 **>99 时显示 `99+`**（官方默认模式的行为）。
- **凡有段评的段落都有气泡**：真机那本书 36 段全部有段评，因此 36 段都会出现气泡（此前只有 1 段）。
- 气泡是段落 `TextSpan` 的一部分，因此**两种阅读模式都自动生效**（分页与滚动），无需分别实现。
- 滚动的 maxScroll、分页的高、插图、位置保存与恢复均未改变语义（既有 92 项阅读器测试全绿）。
- 大字号（1.8 倍）与 `99+` 已覆盖，无溢出。
- 段评仍**不影响正文可用性**：加载失败或为空时一个气泡都不画，正文照常。
- `ParagraphIdeas.showsBubble` 是新的公开判据；`ChapterIdeas.bubbleCounts` 给出「段号 → 显示数字」。
- 气泡增加了一个 `WidgetSpan`，段落测量的占位符数量从 1 变为 1~2，行内偏移换算多了一个常量；这是该方法主要的可读性成本，已就地注明。
