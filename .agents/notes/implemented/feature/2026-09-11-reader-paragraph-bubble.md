# Agent Note: 阅读器正文内联段评气泡

Status: implemented

## Problem

段评此前只在阅读器菜单里有一个「段评 · N」入口，点开是**按段落分组的底部面板**。正文本身没有任何标记：读者读到一段有话想说的地方，看不出这段有没有人评过，必须先收菜单、找入口、再在面板里翻到那一段。

官方客户端是在正文里直接画气泡的，这也是用户这次要的效果。

需要先说明的是：本文推翻了自己上一篇结论。[章评／段评端点](2026-09-10-chapter-ideas-endpoint.md) 当时把内联角标列为**否掉**的方案，理由是「需要改动分页布局逐行的命中测试，风险高于收益」。这次做了，做法与当时的顾虑不同——见下。

## Decision

在段落**末行末尾**内联一个圆形计数气泡，点它直接打开该段的段评。

### 哪些段落有气泡：复刻官方的门槛

上游给每段返回 `count`、`bubble_data` 和 `infos`。实测一个真实章节（48 段）：

| 判据 | 通过段数 |
|---|---|
| `count > 0` | **48 / 48** |
| `bubble_data["3"].count > 0` | **21 / 48** |

也就是说**每段都有段评**，若按 `count > 0` 画气泡，全章会密密麻麻全是气泡。官方因此设了一道门槛——反编译 `CSSParagraphCommentReaderService`：

```java
Map map = paraIdeaData.bubbleData;
paraBubble = (ParaBubble) CollectionKt.getOrNull(map, 3);   // key 3
if (paraBubble == null || paraBubble.count <= 0) return;    // 不画
int i2 = paraIdeaData.count;                                 // 画的是这个
```

**门槛读 `bubble_data[3].count`，气泡里印的是顶层的 `count`**——两者不是同一个数（实测某段 `count=10` 而 `key3=0`，另有段 `count=287` 且 `key3=287`）。这就是官方"只有部分段落有气泡、且数字比肉眼可见的讨论多"的原因，本地复刻了这一对语义。

`bubble_data` 缺失时无从设门槛，退化为「有段评就画」，避免整章一个气泡都没有。

### 几何规格来自官方常量

反编译 `n02/e.java` 得到按正文字号分档的尺寸（dp），以及 `b.java` 的定位：

| 正文有效字号 | 文字 | 气泡宽 × 高 |
|---|---|---|
| ≤ 19 | 8 | 26 × 24 |
| ≤ 29 | 9 | 28 × 26 |
| > 29 | 10 | 32 × 30 |

- 与段落最后一个字形的水平间距 **6dp**（`b.java` 里气泡 `left = 末字形 right + gap`）；
- 计数 ≥ 1000 时文字缩小 1 档、方框改为与高同宽；标签显示 `999+`；
- 气泡与末行**垂直居中对齐**（`top = 行 top + (行高 - 气泡高) / 2`）；
- 定位是 `left = renderRect.right + gap`，并且**若放不下则回退到行尾内侧**（`if (i + iB > iE) i = iE - iB;`）——这个回退交给文本排版自然完成。

颜色不在官方常量里（它按皮肤取 drawable），因此**没有照抄配色**，而是从阅读主题的 `mutedTextColor` 派生一层 16% 透明底——与官方按皮肤取色的思路一致，且在四种阅读背景和夜间模式下都成立。

### 实现方式：气泡进入文本流，不是叠加层

关键决定是**不**把气泡做成覆盖在正文上的独立定位层，而是**排进段落自己的文本流**：把气泡作为 `WidgetSpan` 追加在段落 `TextSpan` 的末尾，并用 `TextPainter.setPlaceholderDimensions` 给它占位。

这样做的好处是命中的是真正的排版结果：

- 气泡天然出现在**末行末尾**，段末放不下时随文本一起换行，不会盖住字；
- 分页测量与绘制用**同一个 span**（`reader_chapter_layout.dart` 里测量用的 `block.span` 就是渲染用的那个），不存在"量出来一个高度、画出来另一个"的偏差；
- 段落内的字一个都没动，气泡纯属追加（有测试断言三段正文仍完整渲染）。

代价与边界：

- 增加了一个 `WidgetSpan`，所以 `\uFFFC` 占位符从 1 个（首行缩进）变成 1~2 个，行内偏移的换算相应调整（`leading` 常量）；
- **"只含气泡的行"不产生切分点**（`cuts` 只在 `starts[i] < text.length` 时新增），因此气泡永远跟着前一行走，不会单独占一页；
- 分页模式下气泡若落在片段被裁切的位置会被 `ClipRect` 裁掉，与正文同一处理，不另做补偿。

### 段评到达要重排版

`_prepareLayout` 原本只在 spec 变化或翻页模式切换时重算布局，而**段评与这两者都无关**。因此加了 `_ideasRevision`：段评变化时 +1，缓存布局记住自己是用哪个 revision 量的，不一致就重算。

这里改动时我自己引入过一个缺陷并被测试当场抓到：重用的判据只看了 spec 与模式，导致段评到达后**直接复用旧布局，气泡永远不出现**（正文正常，只是没气泡——最容易被当成"没数据"的那类静默失败）。修法是把 revision 一并纳入重用条件，同时保住原本"切分页模式不重新测量"的优化。

## Alternatives considered

- **按 `count > 0` 画气泡**：实现最简单，但实测 48/48 段全部通过，整章会铺满气泡，与官方观感差得远。改为复刻 `bubble_data[3]` 门槛。
- **门槛与显示都用同一个数**：省掉一层解释，但会与官方数字不符——实测门槛通道为 0、顶层 `count` 却有值的段落大量存在。两者分开保留。
- **用 `bubble_data[1]`（实测等于 `count`）当门槛**：数值上与 `count` 相同，等于没有门槛。否掉。
- **把气泡做成正文之上的 `Stack`/`Positioned` 覆盖层**：不必碰 `reader_chapter_layout.dart`，但需要自己按行高算位置，且测量高度与绘制高度会各算一遍；换行、两端对齐、插图、大字号下都要各自处理。选择排进文本流，让排版器负责定位。
- **给非末行也支持气泡**：官方就是末行，且末行定位不需要额外的行内偏移映射。不做。
- **照抄官方皮肤 drawable 的颜色**：官方颜色来自皮肤包（`d().g0()` 等），本项目没有对应皮肤体系，硬编码会在四种阅读背景之一上不可读。改为从主题派生。
- **气泡里显示段评正文摘要**：`infos` 实测恒为空（48 段里 46 段为空数组，另 2 段虽带 id 但 `count=0`），正文要再走一跳 `insert_comment_ids`。官方面板里气泡也只有数字。不做。
- **点击气泡跳转段评列表页**：官方是弹面板；本项目已有 `ReaderIdeasSheet`，复用它成本最低，且不新增导航层级。

## Consequences

- 正文里能直接看到哪些段落有讨论及数量；点气泡**直接打开面板并展开那一段**（`initialParaIndex`，面板会把该段滚入视野），不再需要自己翻找。
- 气泡是段落 `TextSpan` 的一部分，因此**两种阅读模式都自动生效**（分页与滚动），无需分别实现。
- 实测口径：真实章节 48 段中 21 段出现气泡；滚动的 maxScroll、分页的高、插图、位置保存与恢复均未改变语义（既有 92 项阅读器测试全绿）。
- 大字号（1.8 倍）与 `999+` 已覆盖，无溢出。
- 段评仍**不影响正文可用性**：加载失败或为空时一个气泡都不画，正文照常。
- `ParagraphIdeas.showsBubble` 是新的公开判据；`ChapterIdeas.bubbleCounts` 给出「段号 → 显示数字」。
- 气泡增加了一个 `WidgetSpan`，段落测量的占位符数量从 1 变为 1~2，行内偏移换算多了一个常量；这是该方法主要的可读性成本，已就地注明。
