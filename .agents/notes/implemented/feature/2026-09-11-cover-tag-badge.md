# Agent Note: 卡片封面角标（上新／爆款）

Status: implemented

## Problem

用户对照官方客户端截图指出，部分卡片封面左上角有「上新」标记，本 App 的卡片没有：首页卡片左上角只有类型标签（短剧／漫剧），搜索卡片右上角只有类型徽章。

按之前几轮的做法，先确认这是「没解析」还是「拿不到」，两种情况的做法完全不同。

角标做完后用户反馈**首页推荐页仍然看不到**。复查发现是两个不同层面的问题：一个是首页数据链路把角标丢掉了（真正的缺陷，见下），另一个是推荐页的数据源本身很少带角标（上游行为，不是缺陷）。

## Decision

解析上游卡片自带的角标并渲染在封面上，**文字与配色都取自上游**。

### 首页曾经把角标丢掉

`HomeNotifier._forceKind` 需要为每个分类改写 `kind`，而它当时是**手工重建** `MediaItem`：

```dart
.map((item) => MediaItem(id: item.id, title: ..., kind: kind, ...))  // 没有 tag
```

新增字段不会被带上，于是**所有首页分类的角标都被丢弃**（漫剧 tab 恰恰是角标最多的来源，走的就是这条路）。这正是「模型和组件都测过了，页面上却什么都没有」的原因：测试覆盖了解析和渲染，却没覆盖首页这条真实链路。

修法是给 `MediaItem` 加 `copyWith`，让 `_forceKind` 用 `item.copyWith(kind: kind)`。这样重建不再是逐字段抄写，以后加字段也不会再被静默丢掉。`_forceKind` 是首页唯一的手工重建点（`library_page._historyItem` 是从历史记录构造，与角标无关）。

### 数据在哪

角标就在卡片对象上，与 `title`/`cover` 同级，不在 `book_data` 里：

```json
"tag_info": {"text":"上新","bg_color":["#00B876","#15D791"],
             "dark_bg_color":["#009962","#11B279"]}
```

实测各来源（本地后端真实响应）：

| 来源 | 字段 | `text` 取值 |
|---|---|---|
| 漫剧首页 `tab_type=24` | `tag_info` | `上新`×9、`爆款`×1 |
| 漫剧搜索 `tab_type=11` | `tag_info` + `cover_tag_info_list` | `漫剧`×6、`小说改编`×2、`热门`×1、`上新`×1 |
| 推荐 `tab_type=2` | 无 | — |
| 看剧 `tab_type=8` | `tag_info` | 空文本×6（已被忽略） |

客户端此前只在 `_textBlob`/`hasTag` 里把 `tag_info` 当作存在性判断（用于识别内容类型），从未解析文字或渲染。

### 配色必须来自上游

同一个字段在不同标签下配色不同：

- `上新` → 绿 `#00B876`→`#15D791`
- `爆款` → 红 `#F44018`→`#FF6459`
- `热门` → 橙 `#FF9052`→`#FA6725`

上游还分别给明色（`bg_color`）和暗色（`dark_bg_color`）两套。写死任何一套都会与官方不一致，也会在暗色模式下难看。

### 只渲染带配色的角标

这是从数据里读出来的判据，不是猜的：**有渐变的是推广角标，没有渐变的是类型标签**。

搜索结果的 `tag_info` 会同时承载类型名（`漫剧`、`小说改编`，无配色）和推广角标（`上新`、`热门`，有配色）。而卡片本身已经显示内容类型（首页左上类型标签、搜索卡片右上类型徽章），若无差别渲染，搜索卡片会出现两个「漫剧」。因此以「上游是否提供渐变」为判据：无渐变的标签由既有的类型标签承担，不重复渲染。

`MediaTag.hasColors` 就是这个判据；两个卡片都在渲染前用它过滤。

## Alternatives considered

- **只解析、只渲染 `上新`**：改动最小，但实测同一字段还会返回「爆款」「热门」，只认一个标签会在其它卡片上静默丢失标记，且无法解释为何忽略。
- **按标签文字硬编码颜色**：官方配色可能变化，且暗色模式需要另一套；上游已经给了两套色，硬编码属于重复且更快过期的知识。
- **不加 `hasColors` 判据，凡有 `tag_info` 就渲染**：首页无影响（该来源的标签都带色），但搜索卡片会出现类型名重复角标（如左上「漫剧」+右上「漫剧」）。否掉。
- **用「文字是否等于类型名」去重**：需要维护类型名与上游用词的对照表，比「有没有配色」更脆弱；上游改文案就会失配。
- **只加首页卡片，不动搜索卡片**：搜索响应同样带角标，同一部作品在首页有标记、搜索里没有，看起来更像 bug。两处共用一个 `CoverTagChip`，保持一致。
- **把角标画成图片**：上游只给文字与色值，没有图片资源；自绘渐变与文字即可，且能跟随字号缩放。
- **`_forceKind` 里逐个补上 `tag: item.tag`**：能修好当前这个字段，但保留了「手工重建」这个缺陷模式，下次再加字段还会静默丢失。改为 `copyWith`。

## Consequences

- 首页与搜索的卡片封面左上角显示上游角标，配色与官方一致，并支持明暗两套。
- 角标是**通用**能力，不绑定「上新」：`爆款`、`热门` 以及将来任何带配色的标签都会自动显示。
- 首页卡片的类型标签与角标并排放在同一行（角标用 `Flexible`，过长文字省略而不溢出封面）。
- 搜索卡片的类型徽章仍在右上，角标放左上，两者不冲突；搜索卡片额外用 `ConstrainedBox` 限制角标宽度。
- 无渐变的标签会被解析并保留在模型里，但不渲染。模型忠实记录上游内容，是否展示由卡片决定。
- `tag_info` 的文字会参与内容类型识别（既有行为，`_isManjuItem` 读标签文本），因此测试若用「漫剧」当角标文案会改变条目类型 —— 这是既有逻辑，不是本次引入。
- **各 tab 的角标密度取决于上游**（实测真实响应）：
  - 漫剧 tab（`tab_type=24`）：12 项中 10 项带角标，全部为带色角标（`上新`×9、`爆款`×1）。
  - 小说 tab（`tab_type=2`）：25 项中 0 项带角标，上游不返回 `tag_info`。
  - 搜索（`tab_type=11`）：标签大多是无配色的类型名（`漫剧`、`小说改编`），按判据不渲染；带色的只有少数（`上新`、`热门`）。
  所以角标实际上是**漫剧推荐流**的特性。推荐页原先的漫剧分组来自搜索，因而几乎看不到角标；该来源已改为漫剧推荐流，见[推荐页漫剧来源决定](2026-09-11-home-manju-source.md)。
- `MediaItem.copyWith` 无法把可空字段清成 null（用 `??` 实现，不引入哨兵值）。当前调用方只改 `kind`，不受影响。
