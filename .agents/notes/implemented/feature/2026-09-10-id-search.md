# Agent Note: 作品 ID 精确搜索

Status: implemented

## Problem

用户拿到作品 ID 后，搜索框只能将数字作为关键词传给搜索接口，无法可靠找到对应作品。小说、短剧、漫剧、漫画和听书的作品 ID 已能被现有详情接口解析，但搜索页尚未使用这个能力。

## Decision

同一个搜索框自动识别 15 至 20 位纯数字，并支持显式 `id:作品ID` 前缀。`1984` 等短数字保留关键词语义，ID 结果页提供“按关键词搜索”入口。请求、比较和存储均使用原始数字字符串，避免精度损失。

`ApiClient.lookupMediaById` 优先请求 `/api/v1/books/{id}/detail`，无有效匹配或请求失败时再读取 `/api/v1/books/{id}/directory` 中的作品元数据。手机实测五类作品均能从详情取得名称与类型，目录则兼容缺少详情记录的作品。两个接口均已内置在 Android 后端中。

`parseMediaIdResult` 只接受具有真实标题且 ID 完全相同的作品元数据，只遍历 `data`、`book_info`、`book_data` 包装。章节列表和推荐作品不会被作为精确匹配，也不会用输入 ID 创建占位作品。短剧详情用 `genre=203` 表明类型，漫剧为 `205`；视频类的作品 `book_id` 显式保留为系列 ID，以便复用目录和播放历史。

ID 查询一次取得作品，五个分类共享该次查询状态并按实际类型展示，不执行关键词分页。切换分类复用已取结果；重新搜索、清空和关闭页面继续受查询代次保护。上游明确作品不存在的 `101104` 结束查询；HTTP 404、空元数据或其他错误允许尝试目录。已有请求错误保留重试能力，不能被后续空结果掩盖。

实测不存在的 ID 在详情中返回 `101104`，继续请求目录却可能超时。因此明确的“不存在”直接返回无结果，目录回退只用于详情不可用或没有有效元数据的情况。

关键词分类和游标逻辑沿用[搜索分类修复](../bug-fix/2026-09-10-search-categories.md)。

## Alternatives considered

- **仍把 ID 作为关键词传给搜索接口**：可以完全复用原分页流程，但它不能保证按 ID 匹配，也可能返回标题含数字的其他作品。详情接口直接接受作品 ID，更适合精确查找。
- **新增独立 ID 搜索页面或必须手选模式**：能彻底消除数字书名歧义，但每次粘贴作品 ID 都需要额外操作。当前采用长数字自动识别、短数字显式前缀，并提供关键词切换入口。
- **同时请求小说、短剧、漫画和听书的专属详情**：可能覆盖更多旧接口，但会重复查询并产生不同类型的候选记录。已实测的通用作品详情覆盖五类，因此采用详情优先、目录按需回退。

## Consequences

用户直接粘贴作品 ID 就能取得可打开的真实作品，保留原类型和系列身份。代价是失败或缺少详情时最多发生两次顺序请求，目录响应可能包含较长的章节列表，因此解码和元数据解析继续在后台 isolate 中完成。

本入口查作品或系列 ID，不把章节、单集或用户 ID 当作作品；长数字书名可以手动切换关键词搜索。若上游增加非数字作品 ID 或新的类型编号，应根据接口证据调整识别规则。
